## Completed Asterinas integration work

Commit `ff14de058...` adds two production helper crates.

`kernel/libs/aster-uapi`:

- defines the production `UserIoVec` ABI type;
- provides checked entry-address and length/truncation helpers;
- is called by `kernel/core/src/util/iovec.rs`;
- contains five Kani proofs and host/Miri tests;
- exports layout data only under the non-default `syssec-layout` feature;
- contains the `fuzz_iovec` cargo-fuzz target.

`kernel/libs/aster-fd-protocol`:

- defines reserved versus installed FD slot state;
- hides reserved descriptors from lookup, close, fork, and reuse;
- contains host tests and a bounded Loom model;
- is used by `FileTable`, `pipe2`, and clone pidfd paths so fallible user
  copyout occurs before descriptor visibility.

Commit `5275e22a9...` adds:

- `AUTO_TEST=syssec` and `SYSSEC_CASE=<path>`;
- a generic executable wrapper for one initramfs regression binary;
- `QEMU_HOSTFWD=off` for isolated tests that do not need guest services;
- a structured partial-EFAULT pipe-read case with begin/end markers.

## Runtime diagnosis so far

The minimal runtime command is:

```sh
docker run --rm -it \
  --privileged \
  --network=host \
  -v /tmp/asterinas-syssec-v03.cIgpRt/asterinas:/root/asterinas \
  -w /root/asterinas \
  asterinas/dev:0.18.1-20260805 \
  make run_kernel \
    AUTO_TEST=syssec \
    SYSSEC_CASE=io/file_io/partial_efault_json \
    TARGET_ARCH=x86_64 \
    ENABLE_KVM=0 \
    QEMU_HOSTFWD=off
```

Do not bind host `/dev` for this rootless Docker/TCG path. Earlier attempts
failed in Docker before QEMU with `/dev/pts` ownership or `/dev/console`
permission errors.

Diagnosis sequence:

1. Default QEMU user networking failed before guest start because one of seven
   service `hostfwd` rules could not bind.
2. Fixed candidate ports failed the same way. This ruled out one random port
   collision and motivated `QEMU_HOSTFWD=off`.
3. Passing a C binary directly as `--init-args` caused BusyBox `sh` to parse
   the ELF. `run_syssec_case.sh` now validates and `exec`s the binary.
4. The guest then emitted valid result markers. The Makefile postcondition
   rejected the final marker because serial output ended the line with CRLF.
5. The committed check matches the marker prefix. It returns zero against the
   captured `qemu.log`; a full TCG rerun after this final one-line change is
   still pending.

Captured Asterinas observation:

```json
{
  "case_id": "pipe-partial-efault-read",
  "exit_kind": "normal",
  "return": -1,
  "errno": 14,
  "first_byte": 65,
  "remaining_return": 2,
  "remaining_errno": 0,
  "remaining_byte_0": 65,
  "remaining_byte_1": 66
}
```

A source-equivalent dynamically linked host binary produced the same fields on
the current host Linux kernel. This is useful smoke evidence only: it is not
the same static binary and the host kernel is not the pinned Linux oracle. Do
not classify this case as a mismatch or finding.

The attempted host static build failed because the host environment does not
provide static libc. The initramfs build does contain a static binary inside
the container Nix store, but it has not yet been exported into run evidence.

## Unfinished work

### Runtime and differential engines

No runtime adapter is committed in aster-syssec yet. It still needs:

- runtime target, result, guest protocol, and oracle-comparison schemas;
- an Asterinas QEMU process adapter with watchdog and failure classification;
- export and hashing of the exact static test binary;
- a pinned Linux image/revision/config and VM runner;
- case-specific comparison relations and normalization;
- distinct outcomes for guest panic, guest hang, test timeout, QEMU failure,
  invalid protocol, and oracle failure;
- import of a mismatch as a candidate, never an automatic security finding.

The runner must set `QEMU_HOSTFWD=off`. A host-forwarding error is
`tool-error`, not a guest crash.

### Fault, pause, and trace bridge

Not implemented:

- boot-time fault plans;
- deterministic pause/release points;
- test-only `/dev/syssec` control protocol;
- the producer for the existing trace-event schema;
- opaque object IDs and address-redaction checks;
- release-build proof that hooks and control interfaces are absent.

### Kernel sequence fuzzing

Only the host `fuzz_iovec` target exists. There is no guest sequence compiler,
replay corpus, reboot/snapshot loop, syzkaller executor, or per-execution
coverage feedback.

### Specula gates

The existing v0.2 handoff remains analysis-only. The following are absent:

- phase-specific `analyze`, `specgen`, `harness`, `validate`, `confirm`, and
  `classify` execution;
- hash-bound analysis/spec/trace/counterexample approvals;
- Specula result import;
- counterexample-to-runtime request conversion.

### Finding ledger and promotion

There is no durable candidate-to-finding ledger or `promote` command. Runtime,
oracle, impact, duplicate status, schedule evidence, regression location, and
artifact hashes still need to be enforced before promotion.

### Default CI profiles

`run --profile` is implemented, but the bundled profiles do not yet select the
new host targets. The pinned public Asterinas input lacks the production seam,
so enabling those targets now would fail checkout preflight. Add them only
after the seam commits are available from a durable Asterinas revision.
