# v0.4.0 release record

v0.4.0 closes the first Host-to-Runtime verification loop. It retains the
v0.3 Host Verification targets and adds exact binary provenance, isolated
Asterinas and Linux execution, case-specific differential comparison, explicit
safety lanes, and recoverable Runtime CI.

## Release contents

- 11 packaged Host Verification targets across Kani, Miri, cross-target layout,
  cargo-fuzz, and Loom;
- strict guest protocol parsing and normalized Runtime outcomes;
- isolated Asterinas QEMU execution below the evidence root;
- exact static-binary export with source, compiler, linker, ELF, and SHA-256
  provenance;
- pinned Linux 6.18.45 oracle execution of the same binary;
- `partial-efault-pipe-read-v1`, which compares seven declared fields and keeps
  mismatches candidate-only;
- schema-validated `core`, `model`, and `lab` safety classes;
- a separately packaged, manual-only, network-off Lab boundary with case
  execution still disabled;
- an explicit four-stage Runtime target/profile pipeline;
- manual and weekly Runtime CI with fixed Cargo vendors and budgeted evidence.

## Release boundary

v0.4.0 does not claim:

- phase-specific Specula execution or counterexample import;
- executable Lab cases, fault injection, pause/release triggers, or sequence
  fuzzing;
- finding promotion or exploitability classification;
- differential coverage beyond the registered partial-EFAULT contract;
- completion of message-header, control-message, timespec, sigset, or mmap
  Host Verification targets.

The signed annotated `v0.4.0` tag is created only after the release PR and its
required checks pass. It must point to the release merge commit on `main`.
